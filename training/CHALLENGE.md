# 在真实游戏仿真中训练障碍驾驶

这是独立的第二阶段实验。环境复用 `Simulation`、挑战编辑器的 `applyChallengeActors`、原游戏碰撞检测与道路占用；浏览器使用原 `DriveScene` 3D 渲染器，策略直接输出转向和踏板。页面实际执行策略和物理，不是预录回放，也没有内置规则绕行控制器。

## 启动 3D 实验页

```powershell
npm run dev
```

打开 `http://localhost:9999/challenge-lab.html`。如果开发服务使用其他端口，保持同一路径。

1. 默认是原游戏试车场，有一辆挡路的静止汽车。可切换左右车道、修改障碍纵向位置、调整起终点路线米数和时限。
2. 可以导入原挑战编辑器导出的 version=2 JSON，支持其车辆、行人和路径。背景交通默认关闭，已有挑战对象按原逻辑行动，地图建筑仍参与碰撞。
3. 点击“导出当前挑战供训练”，保存到本地。
4. 选择新检查点里的 `policy.json`，通过固定推理样例校验后，点击“开始驾驶”。可暂停、重置并切换跟车/俯视/车内视角。
5. 点击“倒车练习：越过终点后停回来”，检查模型能否从终点后方倒回停车。修改起终点或更新默认障碍会退出这个起步预设。旧 v1 模型也能加载，但页面会明确标注它不支持倒车。

目前起终点以**地图原导航路线上的米数**指定，相距至少 15 米，并与挑战对象保持至少 7 米距离；不是任意路网上自由点击选点。成功要求距终点小于 3 米且速度低于 1 m/s。道路外车身比例超过 10% 持续 0.1 秒判失败；碰撞或任务超时立即结束。页面慢时仿真放慢，不跳过物理子步。

## 训练

```powershell
conda activate jevpilot-rl
python training/challenge_train.py --steps 500000 --run-dir artifacts/rl/reverse-01
```

在 PyCharm 使用 `jevpilot-rl` 解释器，直接运行 `training/challenge_train.py`，不传参数时默认**从头训练 50 万步**并创建带时间戳的新目录。已去掉脚本里写死的旧模型续训路径；只在传入 `--resume` 时续训。完整 rollout 取整后，50 万步实际为 500736 步。

新版 `challenge-structured-v2` 使用 97 维观测和三个连续动作：

| 动作 | 范围与意义 |
| --- | --- |
| 转向 | −1～1，左转/右转 |
| 有符号油门 | 正数前进、负数倒车，0 松油门 |
| 刹车 | 正数 0～1 表示制动力，非正数松刹车；制动优先于油门 |

沿用车辆物理：反向给油先减速再换向，倒车最高 3 m/s（10.8 km/h）。独立刹车只减速并保持停止，不自动倒车。沿路线的进度奖励改为“减小与目标的路线距离”，所以冲过终点后倒车回去也获得正奖励；继续驶离目标不会获得前进奖励。终点坐标缩放扩大到 240 米，以免 200 米任务的目标距离被原来的 80 米尺度裁剪。

所有课程共享同一个模型、动作和停车成功条件：

| 阶段 | 练习 |
| --- | --- |
| 1 | 无障碍，15～25 米到达并停车，30 秒时限 |
| 2 | 倒车恢复：起点基准 0～15 米变化，目标在基准前方 20 米，实际从目标后方 4～10 米开始，带 0～2 m/s 前进余速；无障碍，30 秒时限 |
| 3 | 35～45 米，障碍在行驶路线左侧偏移 6 米，45 秒时限 |
| 4 | 起点 0、终点 60 米；障碍挡在路中间，纵向位置为任务距离的 40%～60% |
| 5 | 起点沿路线 0～15 米变化，行驶 45～70 米，障碍纵向在任务距离的 40%～60%，横向 ±0.75 米扰动 |
| 6 | 起点 0～10 米，行驶 80～200 米；障碍按同样范围变化，90 秒时限 |

**训练布局不是全部固定。** 第 1/3 阶段的距离随机，第 4 阶段距离固定但障碍纵向位置随机；第 5/6 阶段起点、距离、障碍位置都随机。各阶段实际起步还带小幅位置/朝向扰动。倒车课是专门的恢复任务，`spawnS` 指定实际起步位置；其他课程也可以自主倒车。

每回合重新采样，晋级后 75% 练当前阶段、25% 均匀复习旧阶段。每 10 次 PPO 更新（10240 步）自动考试；可用 `--eval-updates` 调整。当前阶段在 10 个固定留出种子上连续两次成功率 ≥80%、碰撞与离路合计 ≤10%，才晋级一级。训练前考试不算晋级票；到达最高阶段后继续练习。晋级从下一次回合重置开始生效。

另外始终考试 **40 个固定完整挑战**：原有 10 个验证种子 2000000000～2000000009，10 个变化起终点且障碍挡路的场景（2200000000～2200000009），10 个倒车恢复场景（2300000000～2300000009），10 个长距离场景（2400000000～2400000009）。阶段考试使用 2100000000～2100000009，训练只采样小于 10 亿的种子。完整挑战不随课程改变，也不进入 PPO 训练；它们用于验证与模型选择，**不是最终独立泛化测试**，不代表未见城市或复杂交通能力。新的综合分数也不能直接与旧版 20 场考试比较。

双击运行目录中的 `report.html` 查看成功率、碰撞率、离路率、超时率和平均距终点曲线，训练中刷新页面读取最新保存版本。阶段曲线和完整挑战曲线分别显示；阶段升级后难度改变，阶段分数不能直接跨级比较。`metrics.json` 保存曲线数据，`evaluation.json` 保存逐场结果，`progress.csv` 保留优化器指标。

完整考试另有 `reverse_success_rate`（倒车恢复成功率）和 `long_success_rate`（长距离成功率），同时写入终端和曲线，防止整体分数掩盖倒车或长距离失败。每场结果包含起点、终点和实际起步路线米数。

`best.json` 按完整挑战的成功率、事故率（碰撞+离路）、超时率、距终点依次选择最佳模型；`latest.json` 指向最新完整检查点。连续 5 次完整考试没有改善会在终端提示检查学习过程，不会自动扩大步数或改变奖励。`policy.json` 仍可在原 3D 实验页加载。不要用 loss 下降或低事故率单独判断学会了驾驶。

50 万步可以作为首轮实验预算，但并非保证学完六级课程。建议观察阶段进度、完整挑战、倒车和长距离成功率；若连续多次没有进展，应检查学习过程，而不是只追加步数。本次仅增加单辆静态障碍下的倒车/长途能力，不等于已经解决拥堵城市驾驶。

使用 `--no-curriculum` 可训练原始障碍任务，不进行自动晋级。

针对编辑器导出的布局训练：

```powershell
python training/challenge_train.py --challenge path/to/rl-challenge.json --steps 200000 --run-dir artifacts/rl/custom-challenge
```

自定义文件可增加 `"task": {"startS": 0, "goalS": 60}`；3D 实验页导出时会自动写入。没有 task 时使用地图原始起终点。`--challenge` 自动关闭课程，按用户布局训练和评估，报告两组曲线此时都是该固定任务。**固定自定义场景不会自动随机改动障碍，因此固定布局上的高分不能视为泛化成绩。**

`--hours 8` 设置最多 8 小时，`--steps` 是本次追加步数上限，取先到者；完整更新之间检查预算。运行目录放置空文件 `STOP` 可以正常停止，Ctrl+C 只保证此前完整检查点可用。恢复命令：

```powershell
python training/challenge_train.py --resume artifacts/rl/reverse-01/step-0000500736 --steps 100000 --run-dir artifacts/rl/reverse-02
```

检查点名以实际 `latest.json` 为准，每次使用新运行目录。恢复强制校验 v2 规范，源码哈希记录在 manifest 中用于追溯，沿用用户的设置不再强制相同，因此编辑步数默认值不会阻止续训。不要在修改物理/奖励/课程后混淆前后实验。恢复课程等级、晋级连续达标次数和历史曲线；不会因为启动时重新考试而多算一次晋级票。保留模型/优化器/步数，从新回合继续；不恢复完整随机状态和环境，不承诺逐步精确恢复。新运行目录的 `best.json` 只比较本次运行中的检查点，旧运行的最佳模型和报告仍保留。尚未进行长时运行可靠性验收。

动作数和观测数已改变，**v1 旧模型不能接着训练成 v2，新版请从头启动**。旧模型文件仍保留，在 3D 页面按原来的 96 维观测、两维前进/刹车动作运行；新版模型用 97 维、三维动作。当前六级课程只覆盖同一试车场道路，不包含多障碍、行人和城市交通课程。

## 模型与感知边界

- v2 为 97 维结构化观测：自车、终点、前方路线、上一步三个动作及最多 8 个附近交通对象/建筑。含车后对象、对象尺寸、朝向和速度；页面显示被容量限制排除的对象数。v1 仍为 96 维。
- 感知来自模拟器坐标，包括遮挡后的对象，**不是相机视觉或真实传感器**。缺失对象有有效位，观测统一固定尺度裁剪。
- 模型使用 PPO MLP。`policy.zip` 用于 Python 续训；`policy.json` 只包含确定性 actor 权重，浏览器逐层计算 tanh 和输出裁剪，不加载任意可执行 Python 对象。
- 导出文件附带 Python 动作样例，浏览器加载时误差超过 1e-5 拒绝运行。模型性能仍取决于训练，接口校验通过不代表会避障。
- 已保存的直路模型属于 `straight-pass-v1`，不能加载到这个页面。旧直路检查点的严格源码校验绑定此前版本；需要用已推送的 `dd4da23` 源码恢复，而不是跳过兼容检查。旧二维回放 HTML 仍可直接观看。

## 历史：自动课程之前的首轮实测

运行 `artifacts/rl/challenge-second`，随机种子 42，训练 153600 步，最后更新累计计时约 145 秒（最终考试另计）。10 个固定验证场景：

| 步数 | 成功 | 碰撞 | 离路 | 超时 | 平均距终点 |
| --- | --- | --- | --- | --- | --- |
| 51200 | 0% | 0% | 0% | 100% | 57.45 m |
| 102400 | 0% | 0% | 0% | 100% | 56.72 m |
| 153600 | 0% | 0% | 0% | 100% | 56.77 m |

模型主要表现为低速或原地等待，**不能宣称已经会绕障**。从直路通过直接升级为“绕障并停车”尚未产生足够成功经验；低事故率在这里是没有完成任务的保守行为。下一实验应在同一 96 维接口内加入短距离到达/停车场景和逐步增加障碍的采样课程，并对照进度奖励与等待成本；不是直接放大训练时长。

以上是旧版实验结果。新增课程已通过专项环境测试、晋级/复习/留出种子测试、1024 步训练和续训烟雾测试，以及固定任务时间预算停止验证。短测试尚无成功样本，只说明工程流程可用，不说明课程已经训练出会驾驶的模型。

此前课程版验证：11 项 JS 强化学习专项测试、7 项 Python 测试通过，生产构建通过，两个导出模型的 Python/JS 动作样例一致性通过。全项目测试为 89 通过、11 失败，失败位于未改动的决策/路网/交通相关测试；完整日志位于 `artifacts/rl/curriculum-tests.log`。烟雾测试报告位于 `artifacts/rl/curriculum-smoke-02/report.html`，续训报告位于 `artifacts/rl/curriculum-resume-smoke/report.html`。

## 倒车 v2 工程验证

15 项 JS 强化学习专项测试、7 项 Python 测试通过，生产构建通过。包含前进转倒车、独立刹车保持、后方障碍感知与真实碰撞、20 个恢复布局可用原始动作倒回停车、600 个课程布局合法性、远距离观测不饱和及 v1 动作兼容。这里只在测试中用固定控制序列验证物理可行性，训练与浏览器驾驶没有加入规则控制器。
